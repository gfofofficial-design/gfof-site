# Finite private member-preview host

This factory supplies a source-only lifetime boundary for the existing member,
collaboration, feedback and owner-review application. The earlier AWS finite
entry serves signing authority; it is not the complete cookie-authenticated
member application. No route, function deployment or access change is included.

`createFiniteAlliancePreviewHost` defaults off. Enabled construction accepts only
an exact Netlify deploy-preview identity and origin, a fixed UTC window of at
most ten minutes, and an explicit application-opening capability. Production
identities and origins refuse. Request data and environment flags cannot select
or extend the window. The real host must pass the trusted Netlify context, not
context copied from a request. These checks are not independent provider attestation.

Preparation is a separate, explicit server operation while the actual application
is closed. It opens one owned capability bundle, invokes the existing canonical
checkpoint preparation and requires its closed result. No request starts this
operation automatically; failed preparation cannot be retried in that instance.
The bundle's `close` must retire the application and every caller-owned database,
storage and signing handle. Source-level closure cannot prove remote sessions ended.

Preparation keeps the existing 25-second budget; application requests retain
40 seconds, with one additional second of admission reserve. Only one operation
can run per host instance. Absolute UTC expiry, monotonic elapsed time, invalid
or backward clocks, cancellation and uncertain construction permanently close
the host. Late construction is retired and late responses are discarded.
Each phase also checks its own wall and monotonic deadline before dispatch and
before returning, so a delayed timer cannot release an overdue response.
Dispatched mutations retain the application's existing unknown-outcome contract;
this boundary does not undo or resend them. Browser cookies, current account
sessions, reviewer identity, signed serving permission and removal checks remain
the existing application's responsibility.

This is not a distributed request cap, fleet shutdown, privilege revocation or
cost cutoff. A frozen provider process may delay timers. Operator cleanup must
still close ingress, terminate exact sessions and independently verify cloud and
database permissions. Actual runtime credentials, initialization/control changes,
reviewer binding, a preview deployment and a full hosted journey require their
reviewed concrete plan and owner decisions. No private data, key or configuration
is bundled by this module, and no service or monitoring is active.

The existing keyboard, error and status-message interfaces remain in place; this
server-only increment does not establish a new accessibility acceptance. Actual
hosted mobile and assistive-technology checks remain release gates.
