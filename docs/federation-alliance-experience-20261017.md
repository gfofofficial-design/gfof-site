# Alliance experience: research and build decisions

October 17, 2026. Prepared for the existing Federation Alliance, not a new external community platform. The owner handles prospective partner outreach. This proposal adds no partner, social account connection, enrollment, prize, provider subscription or automated message.

## Recommendation

Make Alliance a useful place to do something together before asking people to join a competition. Lead with an activity console, a small crew plan and a public project-introduction worksheet. Keep the existing League's recruitment, activation and seven-plus-day return counts separate. The distinctive Federation layer is evidence: useful participation should lead back to a working tool, a dated source or a reviewed contribution.

This is a product judgment from the mechanisms below, not evidence that a feature will produce a particular growth rate or token price. Vendor adoption figures are vendor-reported and do not establish independent market share.

## Implemented review build

### Mission Console

Eight reviewed briefs connect to existing public routes:

1. Repair the Shuttle: spending choices with fictional credits.
2. Lens: source-bound token controls and explicit unknowns.
3. GFOF evidence: a worked October 8 mint/lock record.
4. Lending Lab: an educational loan simulation.
5. The Meridian Relay: a fictional mission for a shared discussion, not synchronized multiplayer.
6. Useful guide: an outline for a tutorial, translation or source-linked explainer.
7. Mobile feedback: a bounded public-flow check, excluding sign-in, warnings bypass, signatures and financial actions.
8. Project introduction: prepare public information for a conversation.

Role and time filters help a visitor choose. Each card has a short brief, a working destination, a visible limitation and an add/remove control. Selections do not mark work completed. The console makes no network request and reads/writes no browser storage.

### Crew Plan

Choose up to three activities. Start with Welcome relay, Evidence workshop or Builder circle; reorder or remove activities and choose a single session, a week or two weeks. Estimated activity time excludes discussion. The resulting plain-text plan can be copied or downloaded; it does not schedule an event, create a member, count a return or submit work.

State exists only in the tab. Clearing or reloading removes that state, while copies and downloaded files remain under the visitor's control. Downloads use browser-created text blobs and release replaced object URLs. Copy feedback has a five-second deadline and selectable manual text. Changing a draft suppresses obsolete copy feedback; an already-started OS clipboard write cannot be physically canceled.

### Project Prep

The worksheet accepts a public project name, a public HTTPS website, an optional Solana mint and one shared interest. Website URLs with credentials, nonstandard ports, query strings or fragments are refused. A supplied mint must decode to 32 bytes. Other chains can be discussed without supplying a mint; the existing station registry remains Solana-only.

Four preparation checkboxes are self-reported. They do not verify identity, consent, source quality or publication approval. The generated text is explicitly a discussion draft and stays in tab memory until copied/downloaded. Editing any source field invalidates the old output. No address book, email field, account connection, file upload, backend submission or automatic Telegram message is added.

### Scope retained

The host-only partner registry and its consent/identity/publication checks are unchanged. TBB, TEB and BAYLA are not listed as agreed partners. The existing League stays prelaunch with no collected member totals; its opt-in fictional example remains separate. Account registration, cloud progress, verified mission events, Watchtower, staking and lending retain their existing gates. The public title and canonical Alliance route remain stable.

## Next features, in order

| Stage | Feature | Evidence needed before activation |
| --- | --- | --- |
| 1 | Test these console routes with a small owner-led community session. | Which activities people choose and whether they finish the intended task; collect feedback deliberately rather than adding invisible tracking. |
| 2 | Publish the first mutually agreed partner station. | Official identity/contact, permission, sources, relationship disclosure and exact listing approval. |
| 3 | Run the first Community League season. | Google/account clearance, explicit enrollment, server-verified events, abuse handling, final rules/dates, reviewed aggregate publication and response ownership. |
| 4 | Add reviewed contributor spotlights and cooperative missions. | A published rubric, independent source review, duplicate handling, consent and correction/appeal procedure. Recognition is separate from recruitment counts. |
| 5 | Telegram mini app, followed by a Farcaster trial if useful. | Real mobile acceptance, validated platform identity where used, opt-in permissions, sharing/privacy review and operating cost limits. No automatic subscription or notification. |
| 6 | Source-linked AI crew guide and organizer recap drafts. | Approved source set, visible citations/dates, deterministic boundaries, input privacy, cost ceiling, evaluation examples and human approval before publication. No automatic token promotion, investment ranking or message sending. |
| 7 | Optional portable progress across approved stations. | Trusted completion records, account recovery/deletion, consent, revocation/correction and a precise credential model. A wallet alone does not establish a unique person. |

Recommended early cadence: one welcoming route, one useful shared activity and a reviewed recap. Later measure eligible joins, first meaningful use and a clearly defined return cohort. Keep volume, outcome quality and retention distinct; a large raw click total does not prove an engaged community.

## Validation and release boundary

The new console tests cover bounded selections, filters, fixed routes, ordering, public-input validation, draft invalidation, timer cleanup, clipboard timeout/late completion and unavailable-download fallback. Existing station and League tests remain part of the same workflow. All 70 offline tests passed locally with synthetic data and no provider/RPC/Auth/model request.

The review PR records the exact candidate, ready preview and subsequent CI/delivery evidence. Real browser and phone checks must retain their actual result and date. This document does not authorize production merge, public signup, a paid prize, hosted configuration changes, monitoring, new permissions or a social integration.
