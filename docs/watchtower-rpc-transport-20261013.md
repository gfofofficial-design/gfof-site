# Restricted RPC transport — prepared, disabled

The server-only transport is prepared against the official [Helius getting-data quickstart](https://www.helius.dev/docs/getting-data/quickstart) reviewed October 13, 2026. Its endpoint is fixed to HTTPS mainnet.helius-rpc.com with one api-key parameter generated inside the closure from an explicitly injected key. There is no caller-selected endpoint, redirect following, cookie credential, environment lookup or live key read.

Only finalized getTransaction requests with JSON/version-zero options and finalized getMultipleAccounts requests for up to twenty distinct accounts with a positive minContextSlot are accepted. Other methods, batch requests, extra keys and unsupported options refuse before fetching. Request IDs are bound before asynchronous work so later caller mutation cannot change response acceptance. This method restriction does not prove an account or transaction occurred and does not independently validate the network's genesis hash or compare multiple providers.

The deadline covers response headers and streaming body reads, including transports that ignore cancellation. External cancellation is respected. Actual decoded body bytes are capped at one MiB; malformed UTF-8/JSON, wrong response IDs, provider errors, unexpected content type and redirects are refused. Errors expose only RPC unavailable, never endpoint/key, body or provider exception details. No retries are performed. Returned top-level fields are projected; the verifier further projects result evidence.

Default enablement is false. A key alone does not activate this module. No HTTP route, worker, subscription, provider request, credential or cloud setting is created. Tests inject a synthetic key and local Response objects only. The verifier-to-transport fixture proves sequencing and two reserved reads, not a live provider, actual transport TLS or chain evidence.

Production use must keep this transport private to the reviewed verifier, whose durable allowance callback reserves every read first. A durable Watchtower allowance adapter is prepared separately, but its live database table and limits are not provisioned; do not reuse the Dossier AI or price-limiter secret/budget. Review actual provider availability, plan/credit costs, TLS/network provenance, allowance concurrency/exhaustion, database budget fit and owner-approved scope before separately authorized activation. Do not log full request URLs in server or observability instrumentation because Helius puts the key in its query parameter.
