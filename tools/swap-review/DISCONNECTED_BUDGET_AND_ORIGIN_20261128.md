# Galactic Swap · Disconnected budget review

November 28, 2026 · Internal product specification and release review

**Check SOL budget** uses the SOL input amount already on the quote page and a total budget typed by the visitor. Compare both as integer lamports. Show the difference before fees and account setup. If the input alone takes the entire budget or exceeds it, say so. A non-SOL input gets a separate message because its SOL fee requirement is unknown. Clear the budget with the quote form's Clear action. The check uses page memory and makes no wallet, quote or provider request.

A visitor can use 0.010 SOL of input and a 0.012 SOL budget to see 0.002 SOL left before other costs. The archived funded build required at least 0.014353487 SOL at the same 0.012 SOL limit. Those archived figures record a failed gross-debit check. The browser's input-only calculation cannot establish the current route's fees or readiness.

## Separate route proof and origin review

- **Keep the disconnected beta useful.** Continue the existing indicative quote and public token research. Jupiter's quote-only `/order` and Metis-only `/build` have different coverage. Record the exact pair, amount, endpoint, timestamp and result when a bounded read is authorized. A route from one endpoint supplies evidence only for that path. [Jupiter Swap API overview](https://developers.jup.ag/docs/swap)
- **Get independent cost evidence.** With separate approval, capture one current unsigned route for the exact mint, fee payer and intended amount. Review its program, accounts and instructions. Use a separately authorized unsigned RPC simulation as supporting evidence and add the base fee, priority fee, tip, account funding and other SOL debits to the input. Use gross debits before any refunds. Require a complete receipt under the approved cap before a funded test can move forward. [Solana unsigned simulation](https://solana.com/developers/docs/rpc/http/simulatetransaction)
- **Test a second route path only as its own candidate.** If Metis still cannot provide a route, a separately approved `/order` request for an unsigned transaction could test a wider set of routers for the same pair. Verify its exact transaction and cost receipt before comparing it with the Metis path.
- **Send the warning to the vendor that displays it.** Record the exact HTTPS URL, wallet name and version, warning text, review commit and whether the warning appeared at connection or transaction confirmation. Include a redacted screenshot and existing ticket reference. For Phantom's unreviewed-domain warning, use the domain-review form linked from its help article. Its transaction simulation warning goes through wallet support with the relevant evidence. Blockaid separately accepts project verification and false-positive reports in its portal. Keep preview access controls and wallet protections in effect. [Phantom domain review](https://help.phantom.com/articles/46274653769619) · [Phantom support](https://help.phantom.com/articles/6953810233619) · [Blockaid portal](https://report.blockaid.io/)

Keep the funded pilot closed until the applicable exact-origin decision, independent under-cap unsigned evidence and separate wallet enforcement approval are recorded. The existing Wallet and Command Deck tools already cover public address research as the disconnected wallet surface. The product keeps the member's wallet in charge of custody and signing.
